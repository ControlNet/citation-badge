# OpenAlex per-publication enrichment

- Date: 2026-10-19
- Enabled by `main.py --openalex` (GitHub Actions passes it, with `OPENALEX_API_KEY` from repo secrets). Code lives in `openalex.py`, which is stdlib-only and receives `requests.get` from `main.py` so the CLI test harness can fake HTTP.
- Cache layout: `dist/<SCHOLAR_ID>/openalex/<author_pub_id with ':' -> '_'>.json`. The file is the cache: `status: matched` (with `fetched_at`, `openalex_id`, `doi`, `publication_date`, `authors`, `venue`, ...) or `status: not_found` (with `checked_at`). Writes are atomic (`.tmp` + `os.replace`); unreadable files count as missing; stray `.tmp` files are removed at the start of enrichment.
- `_promote_profile` deletes `dist/<ID>/` on every successful Scholar refresh, so `carry_over_cache` first moves cached records for publications still listed in the staged `citation.json` into the staged profile. Records for publications no longer on Scholar are dropped there.
- Enrichment runs after the Scholar loop and root mirror, on promoted profile dirs (not `.staging`, which the dist snapshot ignores), only for profiles with a successful `citation.json`, and never fails the run.
- Scheduling: missing file → title search (10 credits); `not_found` older than 7 days → search again; `matched` older than 30 days → free single-work GET by `openalex_id`. Each tier round-robins across profiles. Co-authored papers reuse another profile's record by normalized Scholar title without a request. Caps: 50 paid requests and 120 s per run.
- Matching is strict: normalized title equality, year within ±1, and at least one surname overlap with the Scholar author line; prefer closest year, then non-repository sources over arXiv.
- Live API facts (2026-10-19): `x-ratelimit-remaining` is in credits (keyless 1000/day shared per IP, free key 10000/day = $1). `filter=title.search:` costs 10 credits, `filter=openalex:` 1, `/works/W...` 0. Per-second and daily-budget limits both return 429; `_is_per_second_limit` treats 429 with remaining > 0 and `x-ratelimit-credits-required` <= remaining as per-second (backoff 1/2/4 s), everything else as budget exhausted (circuit breaker for the whole run). The exact header shape of a budget 429 was not observed; every 429 logs its rate-limit headers so the rule can be tuned from CI logs.
- The key is sent as `Authorization: Bearer <key>`, never as the `api_key` query parameter: `requests` exceptions embed the full URL, and those messages reach logs and `summary.md`. Request exceptions are converted to `OpenAlexError` with only the exception class name.
- `publication_date` is `YYYY-01-01` when OpenAlex only knows the year, so the month is ambiguous on January 1st dates.
- The Docker service does not pass `--openalex`: each service refresh runs in a fresh temp dir without the previous `dist`, so a per-paper cache cannot persist there.
- First live run on `-rpiDIoAAAAJ`: 23 matched, 3 not found out of 26; the second run made zero OpenAlex requests.
